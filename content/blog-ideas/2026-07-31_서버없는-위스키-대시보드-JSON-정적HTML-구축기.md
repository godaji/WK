# 서버 없는 위스키 가격 대시보드 — JSON + 정적 HTML로 만드는 실시간 비교 페이지

## 한 줄 요약
매일 수집되는 위스키 가격 데이터를 JSON 파일 하나에 담고, GitHub Pages 위의 순수 HTML/JS로 필터·정렬·검색이 되는 대시보드를 만든 과정과 설계 판단을 공유한다.

## 왜 이 글인가 (가치-대비-가격)
- **독자 가치**: "서버 비용 0원으로 데이터 대시보드를 운영할 수 있다"는 실증 사례. 개발자·데이터 취미자가 자기 프로젝트에 바로 적용할 수 있는 구체적 패턴을 제공한다.
- **차별점**: 6/16 제안('GitHub Pages로 데이터 블로그 굴리기')이 정적 사이트 전반을 다뤘다면, 이 글은 **대시보드 UI — JSON 스키마 설계 · 클라이언트 사이드 필터/정렬 · 자동 갱신 파이프라인**에 집중한다.
- **낮은 한계비용**: CaskCode가 실제로 운영 중인 `deploy/dashboard/`의 코드·데이터·설계 결정을 그대로 소재로 쓸 수 있다. 새로 만들 것이 거의 없다.

## 독자
- 사이드 프로젝트로 데이터 대시보드를 만들고 싶은 개발자·데이터 분석 취미자
- 서버 관리 없이 자동 갱신되는 페이지를 원하는 1인 창작자
- CaskCode 위스키 대시보드를 쓰면서 "이거 어떻게 만들었지?" 궁금한 독자

## 구성 목차
1. **왜 서버를 안 쓰나** — 비용 0원 vs 서버리스 vs 관리형 DB, 트레이드오프 한 장 정리
2. **JSON 스키마 설계** — 위스키 200종 × 5개 소스(면세·마트·데일리샷·해외) 가격을 하나의 JSON에 담는 구조. `수집일` 메타데이터가 왜 필수인지(CMPA-156 데이터 관리 원칙 연결)
3. **클라이언트 사이드 필터·정렬** — 서버 없이 브라우저에서 카테고리·가격대·브랜드 필터 + 컬럼 정렬을 구현하는 패턴. 바닐라 JS로 200행 정도는 충분히 빠르다
4. **자동 갱신 파이프라인** — GitHub Actions cron → Python 수집 → JSON 갱신 → Pages 배포. "매일 아침 데이터가 바뀌어 있는" 경험을 만드는 구조
5. **모바일 퍼스트 테이블** — 좁은 화면에서 5컬럼 가격표를 깨지지 않게 보여주는 CSS 패턴(2컬럼 압축·가로 스크롤 폴백)
6. **한계와 다음 단계** — JSON 크기 한계, 히스토리 차트 추가, 검색 UX 개선 등

## 우리가 가진 근거/소스
- `deploy/dashboard/index.html` — 실제 운영 중인 대시보드 코드
- `data/dashboard/dashboard_latest.json` — 라이브 데이터 스키마
- `data/dashboard/snapshots/` — 일별 스냅샷 누적 이력
- GitHub Actions 워크플로우 — 자동 수집·배포 파이프라인 실물
- CLAUDE.md의 모바일 퍼스트·데이터 관리 원칙 — 설계 결정의 근거
