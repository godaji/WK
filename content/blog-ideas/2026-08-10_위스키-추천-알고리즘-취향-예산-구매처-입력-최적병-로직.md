# 위스키 추천 알고리즘 — 취향·예산·구매처 3가지 입력으로 최적 병을 골라주는 로직

**기둥**: 💻 Code
**한 줄 요약**: 우리가 가진 1,800종 가격·카테고리·캐스크 데이터를 활용해, 독자가 취향(스타일)·예산·구매 가능 채널 3가지만 입력하면 최적 위스키를 추천하는 로직을 설계하고 공개하는 글.

## 왜 이 글인가

- **독자 니즈**: "뭘 사야 할지 모르겠다"가 위스키 입문~중급 독자의 가장 큰 허들이다. 기존 제안(입문 5병, 다음 한 병, 가격대별 추천 등)은 '정해진 리스트'를 보여줬지만, 독자 개인의 조건(예산·취향·구매 가능 매장)에 맞춘 맞춤 추천은 다루지 않았다.
- **자산 활용**: CaskCode는 이미 정규화된 위스키 메타데이터(assets/whisky-list.csv), 멀티소스 가격 DB(데일리샷·트레이더스·코스트코·면세), 카테고리·캐스크 유형·도수 등 구조화된 데이터를 보유하고 있다. 추천 로직의 재료가 모두 갖춰져 있어 한계비용이 낮다.
- **차별화**: 대부분의 위스키 추천 콘텐츠는 필자 주관 기반이다. 데이터 기반 추천 로직을 코드와 함께 공개하면 "왜 이 병인가"를 투명하게 설명할 수 있고, Code 기둥의 기술 콘텐츠로서 SEO·공유 가치가 높다.

## 독자

- 위스키 구매를 고민 중인 입문~중급 독자 (취향은 있지만 선택지가 많아 결정이 어려운 사람)
- 데이터/개발에 관심 있는 독자 (추천 알고리즘의 내부 동작이 궁금한 사람)

## 구성 목차 (안)

1. **문제 정의** — "뭘 살까"를 데이터로 풀 수 있는가
2. **입력 3가지** — ① 취향(스모키/프루티/스파이시/바닐라 등 맛 프로필), ② 예산(만 원 단위 범위), ③ 구매처(트레이더스/코스트코/데일리샷/면세 중 접근 가능한 곳)
3. **데이터 구조** — whisky-list.csv의 카테고리·캐스크 유형·도수와 멀티소스 가격 테이블이 어떻게 연결되는지
4. **필터링 로직** — 예산 범위 + 구매처 가용성으로 후보군 축소
5. **스코어링 로직** — 취향 프로필과 위스키 속성(캐스크, 피티드, ABV) 간 매칭 점수 + 가성비 보정(가격 대비 속성 밀도)
6. **결과 예시** — "스모키 좋아함, 예산 5~8만원, 트레이더스 이용" → 추천 3병과 이유
7. **한계와 개선 방향** — 맛 리뷰 데이터 부재, 개인화 피드백 루프 등

## 우리가 가진 근거/소스

- `assets/whisky-list.csv` — 정규화된 위스키 메타데이터 (canonical_id, 카테고리, 캐스크 유형, 도수, 숙성년수 등)
- `assets/whisky-aliases.csv` — 동의어·오탈자 매핑
- `scripts/normalize_dataset.py` — 멀티소스 가격 정규화 + DB floor 산출
- `data/dashboard/dashboard_latest.json` — 최신 가격 스냅샷
- 기존 블로그 아이디어의 분석 결과 (캐스크별 가성비, 도수별 가성비, 가격대별 추천 등)
