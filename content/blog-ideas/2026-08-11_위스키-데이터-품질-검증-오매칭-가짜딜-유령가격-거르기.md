# 위스키 가격 데이터, 어떻게 믿나 — 오매칭·가짜딜·유령가격을 걸러내는 자동 검증 이야기

**기둥**: 💻 Code
**한 줄 요약**: 매일 4개 소스에서 1,800여 종 위스키 가격을 긁어 하나의 테이블로 만들 때, '틀린 데이터'는 반드시 섞여 들어온다. CaskCode가 오매칭·가짜 할인·유령 최저가를 자동으로 걸러내는 검증(가드레일) 장치를 코드와 실제 사고 사례로 공개하는 글.

## 왜 이 글인가

- **독자 니즈**: 데이터 블로그를 신뢰하려면 "이 숫자를 어떻게 믿나"에 답할 수 있어야 한다. 수집 구조(08-06 파이프라인 글)와 이름 매칭(07-28 정규화 글)은 다뤘지만, **수집된 값이 틀렸을 때 이를 잡아내는 검증 계층**은 아직 소개하지 않았다. 데이터 품질은 파이프라인의 별개 관심사다.
- **자산 활용**: CaskCode는 이미 여러 실전 가드레일을 코드로 운영 중이다. 번들(잔세트) 노이즈 차단, 면세가 국내 최저가 오염 방지, '이미 사라진 옛 저가'를 최저가로 잡는 오류 방지, 회귀 테스트까지 갖춰져 있다. 새로 만들 것 없이 있는 자산을 그대로 설명하면 되므로 한계비용이 낮다.
- **차별화**: 대부분의 데이터 콘텐츠는 '깨끗한 결과'만 보여준다. 반대로 **실제 오염 사례와 그것을 막은 코드**를 함께 공개하면 신뢰가 올라가고, 데이터 엔지니어링 독자에게 SEO·공유 가치가 높다.

## 독자

- 데이터 수집·정제 파이프라인을 만드는 개발자 (크롤링 데이터의 품질 문제를 겪는 사람)
- CaskCode 가격 데이터를 신뢰할 근거가 궁금한 위스키 독자

## 구성 목차 (안)

1. **왜 크롤링 데이터는 항상 더럽나** — 여러 소스, 제각각인 이름, 섞여 들어오는 가격
2. **함정 ① 가짜 딜(오매칭)** — '제임슨'이 '제임슨 18년'에 붙어 −34만원짜리 유령 할인이 뜬 사고, 숙성년수·CS·피티드 토큰이 다르면 다른 제품이라는 규칙
3. **함정 ② 잔세트·번들 노이즈** — 전용잔·기프트세트가 끼면 '한 병 값'이 부풀려진다, `is_bundle_noise` 게이트
4. **함정 ③ 면세가 오염** — 세금 0인 면세가가 '국내 최저가'로 새어 들어온 사고, 면세 리스팅 판별 게이트
5. **함정 ④ 유령 최저가(사라진 옛 저가)** — 전 지점 동일하게 오른 가격인데 기간 내 단순 min()이 이미 없어진 저가를 최저가로 집어 '인상을 인하처럼' 보이게 한 사고, '소스별 최신가 중 최소값' 규칙
6. **가드레일을 코드로 고정하기** — 런타임 자가검증 + 회귀 테스트로 규칙이 재생성 때 되돌아오지 않게 하는 법
7. **한계와 다음 단계** — 우리가 아직 못 잡는 오류, 사람이 봐야 하는 지점

## 우리가 가진 근거/소스

- `pipelines/common/whisky_quality.py` — 번들 노이즈·격리(quarantine) 공통 게이트
- `pipelines/common/source_floor.py` — '소스별 최신 관측가 중 최소값'으로 국내 최저가(floor) 산출
- `pipelines/dailyshot/crawl_dailyshot.py:is_dutyfree_listing` — 면세/해외 리스팅 판별 게이트
- 회귀 테스트: `scripts/test_dailyshot_dutyfree_guard.py`, `scripts/test_youtube_ocr_gate.py` 등
- 실제 사고 사례(내부 규칙 문서에 기록된) — 제임슨 오매칭, 듀어스15년 면세가 오염, 글렌글라사 포트소이 유령 최저가

## CTA / 배포

- 블로그 글로 검증 로직 설명 + 핵심 코드 스니펫·테스트 예시 공개
- 후속으로 각 가드레일의 '잡아낸 건수' 지표를 대시보드에 노출하는 방향 제안

## 난이도·SEO·후속

- **난이도**: 중 (로직·테스트는 이미 존재, 글은 사례 중심 설명)
- **SEO 키워드**: 데이터 품질, 크롤링 데이터 정제, 데이터 검증 파이프라인, 오매칭 방지, 데이터 가드레일
- **후속**: 가드레일별 '차단 건수' 메트릭 시각화 → 별도 Code 글감 / 데이터 신뢰도 페이지로 확장
